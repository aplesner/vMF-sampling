1What was measured

The joint vMF maximum-likelihood problem estimates the mean direction from the sample resultant and then solves a single scalar equation for the concentration:

A_p(κ) = I_(p/2)(κ) / I_(p/2−1)(κ) = R̄, R̄ = ‖ mean(samples) ‖

Five methods were compared, plus device-native variants of the first three. Attribution matters here and is easy to get wrong: the closed form is Banerjee et al. (2005), while Sra (2012) initializes with that value and performs exactly two Newton updates. The closed form alone is not "the Sra estimator."

  1. Banerjee closed form — R̄(p − R̄²)/(1 − R̄²), no Bessel evaluation.
  2. Sra two-step — Banerjee initialization, exactly two Newton updates.
  3. Converged Newton — safeguarded, iterated to tolerance, using Sra's analytic bracket with bisection fallback for out-of-bracket proposals.
  4. SciPy Brent — independent CPU root solve on the scaled Bessel ratio.
  5. Direct likelihood — bounded maximization of ν·log κ − log I_ν(κ) + κR̄, a validation path rather than a solver.

Each of the first three also runs device-native in PyTorch against compiled CUSF iv_log. Three questions are kept strictly separate, because conflating them is how this kind of benchmark usually goes wrong.

The three questions

Numerical approximation. Set R̄ from a high-precision population ratio for a known (p, κ). Every exact solver should recover the generating κ, so this isolates method error from sample noise.

Estimation from samples. Draw independent datasets, reduce each once to R̄, and feed identical values to every method. Report deviation from the high-accuracy MLE for that same sample separately from deviation from the generating κ. The second is not numerical error.

Performance. Time estimators on precomputed R̄ batches, with sample generation and the reduction to R̄ excluded.

The reference is new to this run and load-bearing. An mpmath solver at 50 decimal digits supplies both the population R̄ and the per-sample MLE; it recovers the generating κ to 4.4e-15 across the entire grid, and — unlike SciPy — stays finite everywhere. Without it, the most interesting rows of every table below would be blank.

Three readings

Sra's two steps are weakest at low dimension, not high. At p = 3, κ = 10 the two updates leave 1.9e-6 relative error where iterated Newton reaches 3.8e-12; the pattern repeats at p = 3, κ = 50 and p = 16, κ = 10. From p = 64 upward the two steps are at machine precision. This is consistent with the method's derivation, which targets large p — but it does contradict the natural generalization from a κ = 50-only grid, where the two steps look universally converged.

Banerjee's closed form is better than its reputation in one specific corner. Its error is governed by κ/p, not by p: it improves from 7.1e-03 at p = 3, κ = 1 to 1.5e-11 at p = 4096, κ = 1, then degrades again to 1.2e-05 as κ climbs to 1000 at that same dimension. For high-dimensional, modestly concentrated data it is accurate to ~1e-8 or better with no Bessel evaluation at all — which for embedding analysis is a genuinely useful shortcut.

Direct likelihood maximization is not a solver. It hovers around 1e-8 in the easy cases but fails outright twice — relative error 1.0 at p = 256, κ = 1 and p = 1024, κ = 200 — because SciPy's bounded Brent search hits non-finite values on an objective that is nearly flat near its maximum. Keep it as a validation cross-check, which is what it was always intended for.

3The SciPy breakdown, and why it matters

The NaN column above has a single mechanical cause. scipy.special.ive is the exponentially scaled Bessel function, and it underflows to exactly zero for order roughly 511 and above. Since scipy_log_iv is built as log(ive(ν, x)) + |x|, a zero becomes -inf, and then: 

p=1024 κ=10   scipy_log_iv(511, 10) = -inf     scipy_log_iv(512, 10) = -inf
              Sra two-step   → nan          (inf − inf in the ratio)
              Newton         → 9.99         (bisection stalls; true 10.0)
              CUSF two-step  → 10.000000000000    ✓

p=4096 κ=1000 scipy_log_iv(2047, 1000) = -inf
              Sra two-step   → nan
              Newton         → 999.78       (relative error 2.2e-04)
              CUSF two-step  → 1000.0000000000   ✓

Two consequences worth separating. The NaN is loud and safe: it announces itself. The converged Newton stall is the dangerous one — it returns a plausible-looking number, silently wrong in the third or fourth digit, because the safeguarded solver correctly falls back to bisection when the Newton derivative is non-finite and then exhausts its iteration budget without the score function ever becoming evaluable. A caller checking only for NaN would not notice.

Practical rule. Every dimension that matters for embedding analysis — 768, 1024, 2048, 4096 — is past the point where SciPy's Bessel path can be trusted. Use compiled CUSF iv_log or the pure-PyTorch translation for any work at p ≥ 1024. This makes the numerics work load-bearing rather than incidental: it is not an optimization, it is the difference between a result and a NaN.

This also constrains the literature. The original hyperspherical VAE implementation uses SciPy's ive for its Bessel terms, which is fine at the dimensions that paper reports (up to m = 40, order 19) and impossible at the dimensions worth trying next.

The bias runs in the same direction as the claim

The signed bias is positive in essentially every cell, and it grows precisely as concentration falls. The sample mean's norm is inflated by finite-sample noise, so R̄ is biased up, so κ̂ is biased up. At p = 4096, κ = 10, n = 100 the median signed bias is +40.4 in relative terms.

This is the methodological crux. Anyone fitting a vMF to embeddings wants to claim they are "more concentrated than uniform." That is exactly the direction the artifact points. So a matched null is not good practice, it is the only thing separating the measurement from the artifact: draw n uniform unit vectors in ℝ^p, run the same estimator, and report the observed value against that null distribution — whose mean is not zero. Building it over an (n, p) grid with enough replicates for percentile intervals is millions of sampling calls, which is where the sampler's throughput stops being a convenience and becomes a precondition.

What this permits, concretely

  • GPT-2 / BERT scale, p = 768 with V = 50,257: n/p ≈ 65, so κ must exceed roughly 75 for 1% accuracy.
  • LLaMA scale, p = 4096 with V = 32,000: n/p ≈ 8, so κ must exceed roughly 800. If embedding concentration is actually near 50, the estimate carries about 30% error.

This also favors fitting whole embedding matrices (n = V) over per-token contextual fits, where n is the occurrence count and exposure is far worse — a token seen 20 times and one seen 2 million times are not comparable without frequency-stratified nulls.

7The two papers, and where they meet this code

Hyperspherical VAE (Davidson et al., UAI 2018)

The latent lives on S^(m−1). The prior becomes uniform on the sphere — which is exactly vMF(μ, κ=0) — and the posterior becomes vMF(μ(x), κ(x)), with κ learned per datapoint. That last point is their contribution relative to prior work: Guu et al. (2018) used a fixed global κ, which they argue reduces to adding vMF noise to a deterministic encoder, since the KL then never varies.

The KL against the uniform prior depends only on κ:

KL = κ·A_m(κ) + (m/2 − 1)·log κ − (m/2)·log(2π) − log I_(m/2−1)(κ) + (m/2)·log π + log 2 − log Γ(m/2)

Because I_ν is not autodiff-able, they hand-derive the κ-gradient, and it is built from Bessel ratios:

∇_κ KL = ½κ·( I_(m/2+1)/I_(m/2−1) − I_(m/2)·(I_(m/2−2) + I_(m/2))/I_(m/2−1)² + 1 )
The bridge. A_m(κ) = I_(m/2)(κ)/I_(m/2−1)(κ) in that KL is precisely the quantity bessel_ratio_from_logs_torch already computes for concentration estimation. The estimation half of this repository and the generative half of that paper need the same function. Every term in the gradient above is a ratio of Bessel functions expressible through log_iv differences.

Their sampler is Ulrich (1984): draw v uniform on the sub-sphere, draw the tangent coordinate ω ∝ exp(κω)(1−ω²)^((m−3)/2) by rejection, then map e₁ → μ with a Householder reflection. That is the same algorithm as src/vmf_torch_hh.py, including the m = 3 closed form, and their appendix even notes the reflection can be applied in O(m) by rearranging terms — the rank-one update this repo implements as a fused addmm_.

Their reported acceptance rates run 1.00–1.46 proposals per accepted sample and improve with dimension, since rejection applies only to a univariate density. That table is their entire statement on computational cost: no wall-clock, no batching, no GPU. Which is the gap this repository's benchmark fills.

Results: S-VAE wins reconstruction error at every dimension tested, but its KL grows much faster with m (7.3 → 33.5 over m = 2 → 40, against 7.2 → 23.8 for the Gaussian), so the likelihood advantage evaporates by m = 20 and reverses at m = 40. They attribute this to vanishing sphere surface area, which peaks at m = 7 and tends to zero. Their stated open question is whether a learned latent radius would fix it.

nGPT (Loshchilov et al., ICLR 2025)

Every embedding and weight matrix is normalized along the embedding dimension after each step; all LayerNorm/RMSNorm layers are removed. Matrix–vector products become cosine similarities in [−1,1], weight decay becomes redundant, and LR warmup is dropped. Block updates become a normalized linear interpolation:

h ← Norm( h + α_A ⊙ (Norm(ATTN(h)) − h) ) h ← Norm( h + α_M ⊙ (Norm(MLP(h)) − h) )

The α vectors are "eigen learning rates" — diagonal entries of a learnable variable-metric matrix, read literally as each block's per-coordinate contribution. Networks learn modest steps, 20–30%, with MLP consistently above attention. Reported speedups are roughly 4×, 10×, and 20× in tokens-to-equal-loss at 1k, 4k, and 8k context. The honest caveat they state in a footnote: per-step time is 60–80% higher, because normalizations are unfused, so wall-clock gain is materially below token gain.

nGPT never models a distribution on the sphere. No vMF, no density, no KL, no sampling. Its geometry diagnostics are three ad-hoc proxies: vector norms, weight-matrix condition numbers, and pairwise dot-product histograms. It observes that "embeddings are not uniformly distributed across the hypersphere but instead form clusters" — and stops. Fitting a vMF and reporting a null-calibrated κ̂ is a better-specified version of that same analysis, and cheaper: O(V·d) for R̄ against O(V²) for a pairwise histogram at V = 32,000.

The strongest single lead

nGPT computes logits as z = E_output·h · s_z, where s_z is a learned scaling factor whose mean converges to about 60.8, and whose Table 4 shows it is by far their most sensitivity-critical scaling parameter — mis-setting it costs 3.12% validation loss. But E_output·h is a vector of cosines between unit vectors, so softmax(s_z · E_output h) is a mixture-of-vMF likelihood with a shared concentration. s_z is a concentration parameter that the paper does not recognize as one.

Correction — the obvious version of this test measures the wrong thing. The tempting experiment is to fit a vMF to the rows of E_output and compare its κ̂ to s_z. That is vacuous. Under the NormFace identity, softmax(s_z·⟨ĥ, ŵ⟩) is a vMF conditional p(ŵ | ĥ), so s_z is the concentration of tokens around a given hidden state — not the spread of the unembedding prototypes among themselves. A well-trained unembedding matrix should be close to uniform on the sphere, giving κ_true ≈ 0 and an uninformative comparison whichever way it lands.

The test that actually probes the identity: for many hidden states ĥ, take the emitted token's ŵ, form the angular residual around ĥ, and estimate the concentration of those residuals pooled over ~10⁷ tokens. That is a genuine test of s_z, and at n/p ≈ 10⁴ it is comfortably estimable.

Either way the statistical power is not the binding constraint, which is what the following simulation establishes — at p = 1024 and a true concentration of 60.8, a sample the size of a vocabulary recovers it to well under 1%: 

p = 1024, κ = 60.8  →  population R̄ = 0.05917

  n =  32,000   κ̂ =  61.06 ± 0.15   (0.43% relative error)
  n =  50,257   κ̂ =  60.98 ± 0.12   (0.30%)
  n = 128,256   κ̂ =  60.88 ± 0.10   (0.13%)

So a null result on the correctly specified test would be informative rather than an artifact of insufficient data.

Related work worth knowing

  • Banerjee et al. (2005), JMLR 6:1345 — origin of the closed form, and of the vMF mixture EM whose M-step is κ estimation.
  • Davidson et al. (2019), arXiv:1910.02912 — the direct follow-up, which names the "hyperspherical bottleneck" as a consequence of the scalar κ and fixes it with a Cartesian product of spheres, one κ per factor. Static MNIST: S^40 LL −96.32 → 4-way product −92.65.
  • De Cao & Aziz (2020), arXiv:2006.04437 — the Power Spherical distribution, motivated explicitly by vMF rejection sampling being "slow and numerically unstable in high dimensions." The main competitor to any fast-vMF claim, and the most interesting thing to try to falsify.
  • SphereAR, arXiv:2509.24335 — hyperspherical latents for autoregressive image generation, ImageNet FID 1.34. Evidence that spherical latents in modern generative models are live rather than historical.
  • On κ estimation at p in the thousands with realistic n, the literature is thin and mostly pre-2015 (Schou 1978, Tanabe et al. 2007, Hornik & Grün 2014). That is an open niche, and it is exactly the regime LLM embedding matrices occupy.

8Two capability gaps to close first

Most of the program below depends on one or both of these.

GAP A

Per-row batched (μᵢ, κᵢ) sampling

TorchvMFHH takes a scalar κ and a single μ. Every VAE and per-token-noise experiment needs (B, d) means with (B,) concentrations in one call. The envelope constants a, b, d become (B,) tensors, the rejection loop needs mask-and-refill rather than compaction, and the Householder update becomes row-wise.

GAP B

Stable differentiable vMF KL at large m

The S-VAE KL and its κ-gradient need four Bessel ratios plus log I_(m/2−1), all expressible through log_iv differences. The original implementation uses SciPy's ive and cannot reach m in the thousands — see section 3. A torch.autograd.Function with an analytic backward is what makes an m = 1024 S-VAE possible at all.

E1

Extend the acceptance-rate table

Theirs is a 5×9 grid from 1,000 Monte Carlo samples, stopping at d = 100. Redo at 10⁶⁺ samples, extend to d = 8192 and κ = 10⁶, and add the number they omit: wall-clock per accepted sample. A 1.4× rejection overhead is irrelevant next to O(nd) Householder cost at d = 4096. Also verify the b-underflow series fallback, which activates exactly in the high-κ regime and the paper never discusses.

no model~1 daystart here
E2

The (n, p) bias surface

Map bias, MSE, and the null distribution of κ̂ over p 2–4096, n 10–10⁶, κ 0–10⁴, with enough replicates for percentile intervals. Ship it as a lookup table. Every experiment in groups A and B needs this null, and it is millions of sampling calls by construction — the clearest case where sampler throughput is a precondition.

no model2–3 daysstart here
E3

Bias-corrected κ̂ for high dimension

From E2's surface, fit and validate a correction in the spirit of the classical nearly-unbiased estimators but for p ≫ 1. Deliverable: an estimator that takes the sample size as an argument, which none of the five current methods do. Highest ratio of novelty to compute cost in the program.

no model~1 week
E4

Gradient variance of the S-VAE reparameterization

The g_cor correction term is score-function-style and the suspected variance culprit at large m — the stated reason Power Spherical exists. Measure the κ-gradient variance for g_rep + g_cor against g_rep alone against Power Spherical's pathwise gradient, over m 2–4096. Synthetic objective, no model. Run before C6.

no model~2 days

Group A — inference-only κ analysis of released checkpoints

A1

vMF atlas of embedding matrices

Fit vMF to rows of E_input and E_output across GPT-2, Pythia, LLaMA-2/3, Qwen. Report R̄, κ̂ from all three fast estimators, and excess over the matched null, against d_model and parameter count.

inference only~1 dayneeds E2
A2

Layerwise κ̂ of hidden states

Capture h at every layer over a fixed corpus slice, fit per layer, pooled and grouped by token id. Tests nGPT's central metaphor — each layer contributes a displacement on the sphere with α ≈ 0.2–0.3 — which predicts a smooth monotone κ̂ trajectory in a normalized model against a jumpier one in a standard GPT. The paper never measures this.

inference only1–2 dayshigh value
A3

Per-token κ̂ as a lexical statistic

Per vocabulary item, collect contextual embeddings and correlate κ̂ against unigram frequency, WordNet sense count, part of speech, whole-word vs fragment, and next-token entropy. Hypothesis: an unsupervised polysemy detector. Requires frequency-stratified nulls — see section 5.

inference only~1 dayneeds E2
A4

κ̂ as an attention-head diagnostic

Recompute nGPT's condition-number figure with κ̂ of the row-normalized per-head W_q, W_k, W_v, correlated against condition number and stable rank. Either it tracks conditioning — then it is cheaper than an SVD and comparable across dimensions — or it measures something orthogonal, which is more interesting.

inference only~1 day
A5

Isotropy literature reconciliation

The embedding-anisotropy literature uses average cosine similarity, IsoScore, and participation ratios. A null-calibrated κ̂ is a principled replacement. Reproduce 3–4 published findings and check which survive bias correction. Given that the bias points the same way as the claim, some published anisotropy may be R̄ sampling noise.

inference only2–3 daysneeds E2
A6

Mixture-of-vMF fit, per-cluster κ̂

nGPT asserts embeddings "form clusters." Test it: fit a k-component vMF mixture, sweep k, model-select on held-out likelihood using exact log C_m(κ). The M-step is κ estimation, once per component per iteration, and the E-step needs log C_m at m in the thousands. This is where fast batched estimation becomes load-bearing rather than decorative.

inference only2–3 days
A7

κ̂ along a training trajectory

Pythia and OLMo release ~150 intermediate checkpoints. Plot κ̂ of embeddings and hidden states against step and tokens. Power law, saturation, and does saturation coincide with the loss knee? nGPT's s_z mean grows with tokens; an analogous κ̂ growth is the geometry-side counterpart.

inference only~2 days
A8

Cross-model comparability note

κ̂ is dimension-aware where raw cosine statistics are not: the same R̄ implies very different κ at p = 768 versus p = 4096. Show concretely that ranking models by mean pairwise cosine gives a different and wrong ordering. Small and clean.

inference only~1 day

Group B — robustness and vMF noise injection

B1

vMF noise as an inference-time robustness knob

At layer ℓ, replace h with a draw from vMF(h/‖h‖, κ) and continue the forward pass. Sweep κ from 10⁵ down to 10. On a normalized residual stream, Gaussian noise is the wrong geometry — it changes the norm, and post-Norm its angular magnitude is dimension-dependent. vMF gives one interpretable dial, and E[μᵀz] = A_p(κ) converts κ to a mean angular displacement in closed form using existing code.

inference only2–3 daysneeds Gap A
B2

Calibrate the noise dial from the data

Rather than sweeping blindly, estimate κ̂_ℓ per layer from A2 and inject at c·κ̂_ℓ, so the perturbation is scale-matched to each layer's own geometry. Report the robustness/accuracy Pareto frontier against uncalibrated injection. The tightest single demonstration that the estimator and the sampler compose.

inference only~1 dayneeds Gap A, A2high value
B3

Is κ̂ an adversarial-input detector?

Compare per-layer κ̂ for adversarial, jailbreak, and prompt-injection inputs against clean batches, plus the within-sequence version across token positions. AUROC against max-softmax, Mahalanobis, and energy baselines. κ̂ is one scalar per layer per sequence — cheap enough for online use, unlike a Mahalanobis distance needing a d×d covariance at d = 4096.

inference only~2 days
B4

Randomized smoothing on the sphere

Cohen et al.-style certified robustness with vMF smoothing instead of Gaussian, yielding a geodesic rather than ℓ₂ certificate; the Neyman–Pearson argument should go through since vMF is monotone in μᵀz. Smoothing needs 10²–10⁴ samples per input, so at d = 4096 throughput is the difference between a real experiment and a toy. Budget time for the multi-class certificate derivation.

inference only3–5 daysneeds Gap A
B5

Adversarial training with vMF augmentation

Fine-tune a small LM or ViT with vMF noise at a normalized layer, κ annealed, against Gaussian-noise augmentation and PGD at matched compute. The training-time sequel to B1/B2.

needs training~1 week
B6

nGPT vs GPT under matched angular perturbation

nGPT claims better length extrapolation and well-conditioned matrices; whether it is more robust to representation-space perturbation is untested. Train a small nGPT and a matched GPT, then apply the B1 protocol to both. Self-contained question: does spherical parameterization confer angular robustness, or only optimization speed?

needs training1–2 weeks

Group C — recreating and extending the hyperspherical VAE

C1

Faithful S-VAE reproduction

Dynamically binarized MNIST, MLP [256,128]/[128,256], Adam 1e-3, batch 64, 100-epoch linear KL warm-up, LL by 500-sample importance weighting, d ∈ {2,5,10,20,40}, 10 runs. Targets: d=2 LL −132.50±0.73; d=40 LL −90.87±0.34 (S) against −88.93±0.30 (N). Minutes per run, and the validation harness for both gaps.

needs training1–2 daysprerequisite
C2

Push past the reported dimension wall

They stop at d = 40, attributing degradation above m ≈ 20 to vanishing surface area. With both gaps closed, extend to d ∈ {64…1024} and measure LL, reconstruction, KL, the distribution of learned κ(x), and observed acceptance rate. Three separable predictions: acceptance improves with d per their own Table 5, so it is not a sampling-cost problem; their KL grows 7.3→33.5 over d = 2→40, so check whether it simply swamps reconstruction; and check whether learned κ saturates against a numerical ceiling.

needs training3–5 daysneeds Gaps A+Bhigh upside
C3

Round-trip validation

Sample n latents per x from q(z|x) with the fast sampler, re-estimate with Sra's two steps, compare against the encoder's κ(x). Validates sampler, estimator, and reparameterization gradient at once, and yields a reusable calibration curve for how many samples each d needs.

needs C1~1 day
C4

Does the aggregate posterior match the prior?

The S-VAE's pitch is that the uniform prior is truly uninformative. Test the consequence: pool z over the training set, fit a vMF to the aggregate posterior, and check whether κ̂_agg is distinguishable from the matched uniform null. Sweep d; fit a mixture to detect prior holes. The paper shows only projection scatter plots.

needs C11–2 days
C5

Fixed versus learned κ, quantified

Their criticism of a fixed global κ is theoretical — constant KL is never optimized. Run the missing ablation: learned κ(x) against a swept fixed global κ at every d up to 1024, measuring LL and the entropy of the learned κ distribution. If learned κ collapses to nearly constant at large d, the bottleneck is "the extra parameter stops paying," not "the sphere runs out of room."

needs training~2 days
C6

vMF versus Power Spherical at matched compute

Power Spherical exists specifically because vMF sampling was "slow and numerically unstable in high dimensions." Re-run that comparison honestly: same S-VAE, same d grid, swap only the posterior family, report LL and wall-clock per epoch and gradient variance. The most directly publishable item here — a specific claim in the literature that this repository's engineering may falsify. Either outcome is clean.

needs training~3 daysrun E4 firstmost publishable
C7

Product-of-spheres S-VAE

Implement the S^M0 × … × S^Mk decomposition with one κ per factor on static MNIST, Omniglot, Caltech 101 Silhouettes. Reproduce their static-MNIST result (S^40 −96.32 → 4-way product −92.65), then extend to ambient dimension 256–1024 with many factors. k factors means k simultaneous samplers with different (μ_j, κ_j) — exactly the Gap A workload.

needs training3–5 daysneeds Gap A
C8

S-VGAE link prediction

Reproduce their Table 4 (Cora 92.7→94.1 AUC, Citeseer 90.3→94.7, Pubmed 97.1 vs 96.0). Then close their loose end: they omitted d_z = 64 for S-VGAE because it ran out of memory, and Pubmed — the largest graph — is the one dataset where their method loses. Run d_z ∈ {64,128,256} with the allocation-conscious in-place sampler and determine whether the Pubmed loss is a capacity limit or the hyperspherical bottleneck.

needs training~2 daysfree win

Group D — nGPT-flavored training experiments

D1

vMF as an explicit output distribution

Replace nGPT's s_z with a properly parameterized vMF concentration, initialized from the geometry via the estimator, and check whether its outsized sensitivity disappears. Cheap precursor first, inference only, ~1 day: does mean(s_z) ≈ 60.8 match κ̂ of the output embeddings at d_model = 1024? Section 7 shows the test is well-conditioned.

precursor: inference onlyfull: needs training1 day / 1–2 weeksbest lead
D2

Is the residual stream a vMF random walk?

Model the layer transition as h_(ℓ+1) ~ vMF(h_ℓ, κ_ℓ), estimate κ_ℓ from empirical transitions, and test whether it is determined by α_(A,ℓ) and α_(M,ℓ) alone. If the fit holds, the result is a generative surrogate of the entire forward pass as a vMF random walk with known per-layer concentration — which can then be sampled to test how much of nGPT's behavior the walk explains. Precisely the explicit spherical distribution nGPT lacks.

inference if checkpoints exist~3 daysmost interesting
D3

vMF-regularized embedding training

Penalize deviation of the embedding matrix's κ̂ from a target — a differentiable "hold embeddings at concentration κ*" regularizer requiring Gap B's Bessel-ratio gradient. Compare against Wang & Isola's uniformity loss, which is a Gaussian-kernel energy rather than a directional likelihood. κ* → 0 recovers uniformity; the open question is whether a nonzero target, matching nGPT's own clustering observation, beats it.

needs training~1 weekneeds Gap B
D4

Eigen learning rates versus measured geometry

Train small nGPTs at several depths and contexts, and test whether learned α_A, α_M are predictable from the per-layer κ̂ trajectory of A2. They report α_A 0.25→0.20 as depth goes 24→36. If a simple relation holds, the eigen learning rates can be initialized or fixed from a cheap geometric measurement — and their own Table 5 shows single scalars cost under 0.3%.

needs training~1 week
D5

Replicate the nGPT speedup at small scale

Prerequisite infrastructure for D1 and D4, at nanoGPT scale on OpenWebText at 1k context. Be explicit about the caveat: the 4×/10×/20× figures are 0.5B/1B on 64 A100s, and the reported 60–80% per-step overhead means wall-clock gain is materially below token gain. Reproducing the ordering is realistic; reproducing the factors is not.

needs training~1 week

10Ordering

Cheap and unblocking first, then inference-only science, then training runs.

  1. E1, E2 — no dependencies, strengthen the existing benchmark, and produce the null tables everything in groups A and B needs.
  2. Gap A and Gap B — 2–3 days total, unblock groups B, C, and D.
  3. A1–A4 — inference-only, laptop scale, first real scientific output. A2 speaks most directly to nGPT.
  4. C1, C3 — S-VAE validation harness and the sampler/estimator round trip.
  5. E4, then C6 — settle vMF versus Power Spherical with the variance mechanism understood first. Most likely publishable single result.
  6. C2 — extend the S-VAE past its reported dimension wall. Highest upside among the VAE items.
  7. B1–B3 — inference-only robustness; B2 is the cleanest demonstration that the sampler and estimator compose.
  8. E3 — the bias-corrected high-p estimator.
  9. D1's precursor — one day, and if mean(s_z) matches κ̂ it is a striking bridge between the two papers.
  10. B4, D2 — highest ambition and risk. B4 is where throughput is a precondition; D2 is where nGPT's missing spherical distribution gets supplied.

11Scope and caveats

Stated plainly, because several of these bound how far the numbers above generalize.

  • Single machine, CPU only. Every measurement is Apple M3 Max, float64, and the local CUSF build has no OpenMP because it is not installed — so the CUSF throughput figures are a floor, not a ceiling. A Linux benchmark should enable and report OpenMP explicitly rather than silently comparing thread configurations.
  • CUDA is untested. The estimators are device-native and CUSF supplies a CUDA path, but no GPU measurement was taken. GPU throughput is only meaningful for large batches, and would need synchronization around the timed regions.
  • float32 not swept. The benchmark supports it; only float64 was run. Subtracting two large nearby log-Bessel values and then forming the cancellation-sensitive Newton derivative is exactly the arithmetic that punishes low precision, so float32 behavior should not be assumed from these results.
  • Sampler-cost rows are not the headline speedups. Repeated because it is easy to misread: those are small-batch M3 Max timings for this study's own data generation. The project's numbers of record remain 126.97× (NumPy) and 99.01× (Torch) at dimension 4096 from calibrated EPYC 7742 cluster runs.
  • The reliability grid is bounded at n = 10⁵. Cells marked "> 100,000" were not resolved, only excluded. E2 is what turns those into numbers.
  • One tempting story does not hold. It would be neat if the S-VAE's reported collapse above m ≈ 20 were a SciPy numerics artifact. It is not: underflow begins near order 511, i.e. p ≈ 1024, far above the dimensions they report. Section 3 explains why nobody has pushed past m = 40, not why 40 was already degrading.
  • The nGPT arithmetic is a simulation, not a measurement. The κ̂ = 61.06 ± 0.15 figure comes from synthetic vMF data at p = 1024. It establishes that the test has adequate statistical power; it says nothing yet about what real nGPT embeddings do.
